Import from Your Own Export

Upload the file your system already produces. Match the columns. See the result before anything is saved.

Until now, getting data into the portal meant reshaping your export to fit our template first. This tool removes that step. You upload the file exactly as your CRM or spreadsheet exports it, tell the portal which of your columns is which, and it shows you precisely what would happen before you commit.

It uses the same rules as the regular Upload button. Nothing about what the portal accepts has changed; only the way you get there.

Where to find it

Sign in as your office's admin and open My Office. You'll see it in two places:

  • The Import from export tab in the left-hand menu.
  • An Import from export button next to Upload on the Contacts and Pipeline pages.

Before you start

  • Export your contacts or your pipeline from your system as a CSV file. Excel files are not accepted; use Save As → CSV if needed.
  • Export everything, not a filtered view. See the note on Replace below.
  • Keep the file under 5 MB and 10,000 rows.

The four steps

1. Choose and upload

Pick Contacts or Pipeline, then choose your file. The portal reads it and tells you how many rows and columns it found. Nothing has been saved.

2. Match the columns

You'll see a table with one row for each portal field. For each one, the portal has tried to guess which of your columns feeds it.

You'll seeWhat it meansWhat to do
✅ matchedWe're confident this is rightGlance at the sample values to be sure
🟡 suggestedProbably right, but a guessCheck the sample values. Change it if they look wrong
⚪ needs a columnA required field with nothing feeding itPick the right column from the dropdown. You can't continue until this is done
⚪ not mappedAn optional field with nothing feeding itLeave it, or pick a column if you have one
The sample values are the point. Under every match you'll see three real values from your file. If the "Contact Name" row shows company names, the match is wrong. Fix it there and then, using the dropdown.

Two things worth knowing on this screen:

  • Names in two columns. If your export has First Name and Last Name separately, the portal usually spots this and combines them. If it doesn't, click Combine two columns… on the Contact Name row.
  • Columns we don't use are listed at the bottom as "will be ignored." That's fine and expected. Nothing disappears without being named.

3. Preview

Click Preview. The portal checks every row and reports, for example: 352 rows in the file. 338 will import. 14 will be skipped. Still nothing has been saved.

Below that, any problems are grouped by type rather than listed one row at a time. Fourteen skipped rows with two kinds of problem is two things to fix, not fourteen.

Download the problem rows. This gives you a file containing just the rows that would be skipped, in your original columns, with a Problem column at the front saying what's wrong with each. Fix those in your own system, re-export, and run the import again.

Why you can't fix rows inside the portal. Every upload replaces what's there. A correction made in the portal would be undone the next time you import. Fixing at source means it's fixed for good.

You'll also see a "worth knowing" box for things that don't stop anything: a broker email we don't recognise yet, contact phone numbers removed under the current sharing guidelines, and so on.

4. Import

Choose how to apply the records:

  • Add on keeps what's already there and adds these. Only for genuinely new records; using it twice with the same file gives you duplicates.
  • Replace all deletes your office's existing records first, then loads the file. The safe way to correct or refresh a full list. You'll be asked to tick a confirmation.

The button tells you exactly what will happen, for instance Replace 340 with 338. Click it, and the import runs.

Send your complete list. If you choose Replace all and the file holds 10 contacts, you'll have 10 contacts. Always export the whole list, never just what changed.
